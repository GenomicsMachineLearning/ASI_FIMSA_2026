# HOW THIS FILE IS USED
# ---------------------
# This is a pip *constraints* file, not a requirements file. It never installs
# anything by itself: it only says "if this package is pulled in, it must be
# exactly this version". Every Tutorial install passes it with `-c`, so all four
# notebooks land on one tested resolution while each installs only what it needs:
#
#   00_setup_check        -c constraints-colab.txt -r requirements-colab.txt
#   01_read_and_visualise -c constraints-colab.txt spatialdata spatialdata-io spatialdata-plot scanpy igraph
#   02_niche_analysis     -c constraints-colab.txt squidpy sopa scanpy seaborn netgraph
#   02b_cell_cell_interaction -c constraints-colab.txt scanpy seaborn bokeh leidenalg
#                             followed by:  --no-deps stlearn   (see below, and ADR-0004)
#   03_vit_gene_expression -c constraints-colab.txt scanpy
#
# Tutorial 3 deliberately installs scanpy ONLY. Its ViT runs on torch, PIL,
# scikit-learn and scipy, all of which Colab preinstalls, so it must not pay for
# the spatialdata stack.
#
# TORCH IS NOT LISTED ANYWHERE IN THIS PIN SET
# --------------------------------------------
# Colab preinstalls torch 2.11.0 with a CUDA build matched to its own driver.
# Naming torch in a requirements or constraints file makes pip re-resolve it and
# can pull a ~2.5 GB wheel set that then fails to see the GPU. Tutorial 3 uses
# whatever torch Colab shipped. The local verification venv installs
# torch==2.11.0+cpu separately, outside this file, only so notebooks can be
# executed headlessly.
#
# THE FOUR SPATIALDATA-FAMILY VERSIONS MOVE TOGETHER (ADR-0003)
# -------------------------------------------------------------
# spatialdata / spatialdata-io / spatialdata-plot / squidpy -- plus sopa, which
# gates on spatialdata>=0.7.3 -- are a single unit. Mixing majors across them is
# the exact failure this pin set exists to prevent. If one is bumped, re-resolve
# and re-verify all five together and update the "Verified" date above. Do not
# bump one in isolation to chase a bug.
#
# THE numpy==2.0.2 HOLD IS THE POINT
# ----------------------------------
# Colab preinstalls numpy 2.0.2 and imports it before the first cell runs. If any
# pin forces numpy above 2.0.2, pip swaps the files under a module that is
# already in memory and Colab demands a mid-session kernel restart -- for a room
# of immunologists, halfway through a Tutorial. 2.0.2 is therefore pinned
# exactly, and the whole stack below was resolved against it. It holds: nothing
# in the workshop stack requires numpy > 2.0.2. The binding floor is
# `scanpy 1.12.3: numpy>=2`, which 2.0.2 satisfies.
#
# stlearn IS INSTALLED WITH --no-deps, AND IS NOT PINNED HERE (ADR-0004)
# ---------------------------------------------------------------------
# stlearn 1.4.1 declares `numpy>=2.4.0`. That floor is incompatible with the hold
# above, and no stlearn release escapes it: 1.3.0 requires numpy<2.0, 1.2.2
# requires scikit-image<0.23, and 1.1.x pins scipy==1.11.4. Since the numpy hold
# exists to protect a room of Participants from a mid-Tutorial kernel restart, it
# wins, and 02b installs stlearn with `--no-deps` instead:
#
#   pip install -q -c constraints-colab.txt scanpy seaborn bokeh leidenalg
#   pip install -q --no-deps stlearn
#
# This is safe to do here and nowhere else because stlearn is a 217 KB pure-Python
# wheel (stlearn-1.4.1-py3-none-any.whl) whose every eagerly-imported third party
# is already in this pin set except two -- bokeh and leidenalg -- which are
# therefore requested explicitly above and pinned in Section A below. plotly,
# rpy2 and IPython are imported inside functions only, and torch/torchvision are
# needed solely by stlearn.image_preprocessing, which 02b never touches.
#
# The cost is real and bounded: `--no-deps` overrides a declared incompatibility,
# so stlearn is only known to work along the paths 02b actually executes, and
# those are the paths verify/run_notebooks.sh runs end to end. If a future stlearn
# genuinely needs a numpy 2.4 API, the documented fallback is a second pin set at
# numpy==2.5.2 for that notebook alone, plus 00_setup_check's restart banner.
#
# DO NOT add `stlearn` to this file. A constraint on a package installed with
# --no-deps is never consulted, so a pin here would be inert and would read as a
# guarantee this file cannot make.

# TWO TIERS, ON PURPOSE
# ---------------------
# Section A pins exactly. These are packages Colab does not ship, or ships in a
# version the stack rejects, so they are installed either way and an exact pin
# costs nothing.
# Section B is floors only, with the tested version recorded in a comment. These
# are packages Colab already ships. Pinning them exactly would force pip to
# re-download and replace a working preinstalled copy -- minutes of install time
# and, for anything Colab has already imported, the same stale-module restart
# that the numpy hold exists to avoid. The floors below are the real declared
# requirements of the stack, so correctness is unchanged.
