# ASI-FIMSA Workshop 2026 -- stlearn, installed on its own with --no-deps
# =======================================================================
# ALWAYS install this file with --no-deps. Never with -r alone, and never
# alongside -c constraints-colab.txt expecting the constraint to bite:
#
#   pip install --no-deps -r requirements-colab-stlearn.txt
#   uv pip install --no-deps -r requirements-colab-stlearn.txt   # verify venv
#
# WHY THIS FILE EXISTS
# --------------------
# stlearn 1.4.1 declares `numpy>=2.4.0`. constraints-colab.txt pins numpy==2.0.2
# because Colab preinstalls and imports 2.0.2 before the first cell, and moving it
# forces a mid-Tutorial kernel restart on a room of Participants. No stlearn
# release satisfies numpy 2.0.2 (1.3.0 wants numpy<2.0, 1.2.2 wants
# scikit-image<0.23, 1.1.x pins scipy==1.11.4), so the resolver cannot help and
# --no-deps is the deliberate override. ADR-0004 records the decision.
#
# WHAT MAKES IT SAFE ENOUGH
# -------------------------
# stlearn-1.4.1-py3-none-any.whl is 217 KB of pure Python. Every third party it
# imports at module level is already in constraints-colab.txt except bokeh and
# leidenalg, which requirements-colab.txt now requests explicitly. plotly, rpy2
# and IPython are imported inside functions; torch and torchvision are needed only
# by stlearn.image_preprocessing, which Tutorial 02b never touches.
#
# The guarantee is exactly this: stlearn works on the code paths
# verify/run_notebooks.sh executes end to end. Nothing wider.
stlearn==1.4.1
